# 棋魂产品与技术计划

日期 2026-11-24

## 产品方向

「棋魂」以中国象棋为主，逐步扩展为集棋类、扑克牌、麻将和地方桌游于一体的休闲棋牌软件。大厅优先展示正在进行的对局和中国象棋，牌类形成独立入口后仍共用棋手档案、好友房和战绩。手机竖屏为主，桌面屏保留棋盘和着法记录并排布局。白色、竹绿色和浅木色贯穿界面。

首发路线选 Android APK。同一份 React + TypeScript + Vite 客户端先在网页检验，再由 Capacitor 将静态资源随应用打包。微信渠道单独适配，先在开发者后台确认产品所属类目、主体资质和允许的运行入口。若需采用微信小游戏运行环境，共用 TypeScript 棋规与棋谱结构，另做 Canvas 和平台接口。普通小程序构建与微信小游戏审核是两项独立工作。本阶段使用临时包名 `com.qihun.board`，正式发布前确认应用名、包名、签名和发行主体。

所有棋种把所用规则版本写入棋谱。象棋首版为休闲裁决，重复盘面第三次出现判和，连续 120 个半回合未吃子判和。围棋休闲首版采用盘面重复限制和固定白贴 7.5，双方停着后按现有盘面计算面积，未清理死子的局面需先走完。赛事规则、连珠禁手和高级引擎具备独立验收门槛。

## 使用流程

1. 打开大厅后可直接用游客身份开局。可创建或切换设备内棋手档案，独立保存对局。真正的账户注册、登录和跨设备同步放在联网阶段。
2. 选棋种、同屏或人机、难度与执先。棋盘支持合法点提示、最近一步、悔棋、认输、浏览规则和快捷互动。局中设置包含声音、音乐、动画、悔棋和提示。
3. 落子立即保存。退出再进入可继续，终局生成历史记录，支持逐手复盘并保存本地备份。先提供胜负统计，再做练习建议、开局库和残局题。
4. 联网先发布好友房。加入房间后由服务端处理对局状态和时间，落子、悔棋请求、认输、求和与聊天均有独立事件。竞技房关闭悔棋和提示。后续增加匹配、积分、赛事和观战。

## 技术与存储

- 棋规层为纯 TypeScript。使用统一的局面、合法动作、推进函数、终局结果和规则版本。棋盘、AI、复盘和未来联机共用棋规。棋子移动、游戏状态和展示数据分离。优先覆盖合法性再提高棋力。
- 客户端为 React + Vite，构建为无外部资源依赖的静态文件。Canvas 绘制连续棋盘线，棋盘落点由可点击元素承接。Web Audio 合成原创落子音和循环背景乐。网页用 localStorage，Android 由 Capacitor Preferences 读写数据。
- 本地首版用版本化 JSON，包含棋手、偏好、分棋种续局和历史棋谱。棋谱保留起始局面、动作、终局原因与时间。单存储写入队列维持顺序，历史按档案隔离。后续历史增大再评估 SQLite 或 IndexedDB，并迁移旧记录。
- 牌类使用独立的规则模块和牌桌界面，与棋类共用档案、回合事件、好友房与复盘入口。规则标识、桌号、座位、开局参数和局号可共用。服务器构建公开视图和每个座位的私有视图，重连分别补发，结局后的牌谱可见性按玩法定义。多局制记录每盘与整场分数。
- 联网阶段采用 Node.js TypeScript + Fastify，HTTP 管理账户、好友和历史，WebSocket 推送实时对局。PostgreSQL 持久化 users、identities、games、moves 和 report 等。对局以编号与手数唯一约束处理重复发包，持久化后广播，重连通过快照与事件序号补齐。Redis 在多实例匹配、限流或房间路由确有需求时接入。
- 联网先用单实例、PostgreSQL 与 HTTPS 部署预发布环境，运行两端联机与断网用例后再谈正式上线。微信服务凭证、发布签名、域名和正式部署资源使用发行方账号。互动从预设表情、短语开始，开放自由消息前完成屏蔽、举报和所需管理机制。

### 联网阶段的数据结构

| 表 | 主要字段 | 用途 |
| --- | --- | --- |
| `users`、`identities` | `user_id`、昵称、`provider`、`provider_subject` | 以用户 ID 归集棋史，对登录提供方和外部用户标识设唯一索引 |
| `games`、`game_players` | `game_id`、棋种、规则版本、状态、当前手数、起止时间、结果、座次 | 对局生命周期、按玩家查棋谱、分配红黑或先后手 |
| `game_events` | `game_id`、`seq`、动作、操作者、`client_action_id`、服务器时间 | 唯一约束覆盖对局序号与各玩家的客户端动作 ID，保障重试幂等 |
| `game_snapshots` | `game_id`、`seq`、局面、计时、棋规版本 | 断线重连和长棋谱加载，定期从已提交事件生成 |
| `reports`、`blocks` | 举报人、被举报人、关联事件、原因、处理状态 | 消息管理，可按房间或用户追踪 |

线上开房、加入房间、查看历史用 HTTP。走棋、请求和棋、房间状态更新及重连用 WebSocket。服务端按 `expected_seq` 和权限检查动作，在事务提交后回传成功及新序号。客户端发现序号跳跃时请求缺失事件或快照。翻棋的未公开棋子留在服务端。离线棋谱由用户选择上传，标记为离线导入，独立于联网竞技积分。

## 开发与验收顺序

1. 建立纯规则层和离线对弈闭环，首先验收中国象棋，再扩展其它棋种。退出恢复、悔棋、终局归档与回放一起验收。
2. 验证桌面和 360–430 px 触屏视口，对局中覆盖连续点击、AI 思考时离开、刷新续局、档案切换和音画设置。规则回归分别覆盖每款棋的特殊走法，并运行多盘合法步推进测试。
3. 构建 Android 调试 APK，验签并记录设备实测范围。正式渠道另做 release 签名，收集真机流畅度、安装兼容性和断网记录。微信客户端开发前先核对平台分类及运行环境。
4. 独立实现好友房、断线重连与账户同步。回放云端棋谱与原局必须一致，再小范围试用。
5. 根据实际使用数据扩展高阶人机、棋谱导入导出、复盘批注、练习题、积分匹配与棋种。
